Crear la suscripción de Azure de Incrementa

Por qué se hace

Incrementa ya tiene su directorio de Microsoft: es donde viven las cuentas @incrementa.la que usa para el correo. Pero nunca ha usado Azure, así que no tiene una suscripción de Azure: el contrato con Microsoft que permite crear servicios en Azure y que define a quién se le cobran.

Sin suscripción no hay dónde instalar el sistema. Por eso ninguno de los accesos siguientes se puede entregar antes. Lo comprobamos el 19 de octubre: la cuenta david.roco@incrementa.la entra al directorio de Incrementa, pero no ve ninguna suscripción.

La suscripción tiene que quedar a nombre de Incrementa, no de David, para que el sistema, los contratos y la facturación sean de Incrementa desde el primer día.

Dónde
Portal de Azure (portal.azure.com) — Suscripciones › Agregar › Pago por uso
Cómo
  1. Entrar con una cuenta @incrementa.la. No con una cuenta personal de Microsoft, Gmail ni Hotmail: si se hace así, Azure crea un directorio aparte y el sistema queda desconectado de las cuentas de Incrementa.
  2. Elegir Pago por uso y registrar la tarjeta de crédito y los datos de facturación de la empresa. No conviene la prueba gratuita: dura 30 días, limita los servicios y después igual hay que convertirla.
  3. Crear una alerta de presupuesto mensual en Administración de costos › Presupuestos, para recibir un aviso por correo si el gasto se acerca al monto que Incrementa defina.
  4. Entregar el Acceso 1 a David.
Quién lo hace
La persona con autoridad para contratar y pagar servicios en nombre de Incrementa, con su propia cuenta @incrementa.la.
Si Incrementa prefiere que David cree la suscripción

David la puede crear con su cuenta david.roco@incrementa.la. Así queda dentro del directorio de Incrementa, igual que si la creara otra persona de la empresa. Para eso necesita:

En este caso el Acceso 1 ya no hace falta: quien crea la suscripción queda como Propietario.

Accesos

  1. 1

    Rol Propietario en la suscripción de Azure

    Dónde
    Portal de Azure (portal.azure.com) — Suscripciones › suscripción de Incrementa › Control de acceso (IAM) › Agregar asignación de rol › Propietario
    Qué resuelve
    Permite crear el grupo de recursos rg-incrementa-prod con todos los componentes del sistema (servidores, base de datos, almacenamiento de contratos y bóveda de claves) y asignar los permisos con que esos componentes se comunican entre sí, sin contraseñas.
    Para quién
    La cuenta david.roco@incrementa.la.
    Quién lo entrega
    Un Propietario actual de la suscripción.
  2. 2

    Registrar el sistema como aplicación de inicio de sesión

    Dónde
    Microsoft Entra ID (entra.microsoft.com) — Identidad › Roles y administradores › Desarrollador de aplicaciones › Agregar asignaciones
    Qué resuelve
    El sistema no tiene usuarios ni contraseñas propias: cada persona entra con su cuenta @incrementa.la, igual que a Outlook o Teams. Para eso, Entra ID debe tener registrado el sistema como una aplicación de Incrementa autorizada a pedir ese inicio de sesión. Este rol permite crear ese registro, incrementa-gestion-prod. No da acceso a correos, archivos ni otras aplicaciones.
    Para quién
    La cuenta david.roco@incrementa.la.
    Quién lo entrega
    Un Administrador global o un Administrador de roles con privilegios.

    Paso adicionalCuando David cree el registro, un Administrador global o un Administrador de aplicaciones en la nube entra a Entra ID › Aplicaciones › Registros de aplicaciones › incrementa-gestion-prod › Permisos de API › Conceder consentimiento de administrador para Incrementa. Se hace una sola vez, y así los usuarios no ven una pantalla de autorización la primera vez que entran.

  3. 3

    Permiso para que el sistema consulte el directorio de usuarios

    Dónde
    Azure Cloud Shell (el ícono >_ de la barra superior de portal.azure.com), ejecutando un comando que entrega David. Este permiso no se puede asignar desde las pantallas del portal.
    Qué resuelve
    Cuando un administrador del sistema da de alta a un usuario nuevo, el sistema comprueba en Entra ID que ese correo existe en Incrementa. Para eso necesita el permiso Microsoft Graph · User.Read.All, que solo lee nombres y correos.
    Para quién
    La identidad administrada del sistema, id-incrementa-backend-prod. No es una persona ni tiene contraseña.
    Quién lo entrega
    Un Administrador global o un Administrador de roles con privilegios.
  4. 4

    Conector del sistema en Claude

    Dónde
    Claude (claude.ai) — Configuración de la organización › Conectores › Agregar conector personalizado, pegando la dirección del servidor que entrega David.
    Qué resuelve
    Que las personas de Incrementa generen, consulten y firmen contratos conversando con Claude, que usa el sistema a través de ese conector.
    Para quién
    Los usuarios de la organización de Claude de Incrementa.
    Quién lo entrega
    El propietario o un administrador de la organización de Claude de Incrementa. Si Incrementa usa planes individuales, cada persona lo agrega en su propia Configuración › Conectores.
  5. 5

    Lista de usuarios del sistema

    Dónde
    El propio sistema, en Administración Global › Usuarios. David crea a cada persona.
    Qué resuelve
    El sistema solo deja entrar a correos registrados en él con un perfil. Quien entra sin perfil ve el mensaje “Sin perfil asignado”.
    Para quién
    Cada persona de Incrementa que usará el sistema desde el primer día.
    Quién lo entrega
    La Gerencia, indicando el correo @incrementa.la y el perfil de cada persona (por ejemplo, Administrador de plataforma).

No se comparte ninguna contraseña ni clave. Cada acceso es un permiso sobre una cuenta, y Incrementa lo puede quitar cuando quiera.

Firma electrónica con Firme.cl

Con Firme.cl, la influencer firma el contrato desde su correo, con firma electrónica simple, y el sistema recibe el PDF firmado automáticamente. Se integra el martes 20 y el miércoles 21 de octubre. El contrato llega a Firme con la rúbrica del representante legal de Incrementa ya estampada por el sistema, así que en Firme solo firma la influencer.

Lo gestiona DavidEn principio, David gestiona directamente con Firme todo lo de esta sección, a nombre de Incrementa. A Incrementa le toca autorizar la contratación de la cuenta y pagar los créditos.

Orden

  1. Incrementa crea su suscripción de Azure (paso inicial).
  2. Incrementa entrega los accesos 1 y 2.
  3. David instala el sistema en Azure.
  4. Incrementa entrega los accesos 3 al 5.
  5. David carga los datos base y hace las pruebas junto a una persona de Incrementa.
  6. David borra las pruebas y entrega el sistema listo para usar.
